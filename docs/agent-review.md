# Agentic review operating contract

The engine reviews introduced correctness and security defects using an immutable diff and source checkout. Findings are advice; a completed run does not establish recall or authorize a merge.

## Commands and trusted policy

Only an original, unedited `/review`, `/review deep`, or `/review codex` comment by the designated maintainer qualifies. The login and numeric ID, human account type, organization association, event type, first run attempt, open PR, and same-repository origin must match. Python re-fetches the triggering command and checks its body and timestamps again before inference and publication. Fork and closed PR commands produce a failed admission job with a fixed reason, without supplying provider secrets.

The exact caller template, named secret mappings, permission ceiling, and immutable shared-engine pin remain mandatory. The credential-free source helper checks GitHub's loaded reusable-workflow identity before engine checkout. Command policy comes from the immutable loaded default-branch revision. For inline replies, executable source is selected before checkout; the loaded merge-ref caller is validated as bounded data and policy comes from a separately resolved immutable default-branch revision. See GitHub's [issue-comment contract](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#issue_comment), [reusable workflows](https://docs.github.com/en/actions/concepts/workflows-and-actions/reusing-workflow-configurations), and [job identity context](https://docs.github.com/en/actions/reference/workflows-and-actions/contexts#job-context).

Caller profiles permit only `[review] instructions` and `[ignore] glob`. The existing 65,536-byte bounded reader rejects symlinks in every path component, non-regular files, malformed TOML, and unsupported fields. Profiles cannot supply Python, tools, callbacks, model policy, spending limits, credentials, or a publication destination.

## Per-depth operator limits

The trusted central `.github/pr-agent.toml` contains `review_depth.default`, `review_depth.deep`, and `review_depth.codex`. Each table must contain these settings:

| Key suffix | Accepted value | Scope |
| --- | --- | --- |
| `max_turns` | Positive integer; booleans, strings, and fractional values are invalid | Each independent pass |
| `max_budget_usd` | Positive finite numeric USD amount; booleans and strings are invalid | Each independent pass |

Errors name the complete key, for example `review_depth.default.max_budget_usd`. There are no defaults or environment overrides. The shipped config deliberately omits both settings for every depth; no example number is production policy. Real values will be set from measured usage on the evaluation set after owner approval. Until then the engine refuses inference.

Default review runs two fresh Sonnet processes, one beginning with the bundle and one with callers/helpers. Deep review runs one Opus process. Codex review runs one Codex pass. A review's maximum configured USD allowance is **passes × max_budget_usd**. Claude's client estimate and Codex's monitored usage estimate can overshoot while an API request is in flight; this allowance is not a guaranteed invoice ceiling. Provider account/project limits remain the billing backstop.

The existing operator settings remain `config.max_model_tokens` (90,000), `config.max_output_tokens` (16,000), and `config.ai_timeout` (300 seconds per pass). The workflow retains its 25-minute job limit. These are operator settings, not advertised model capacities. The output schema permits six candidate findings per pass, ranked by confidence. The union may contain up to passes × six findings.

There is no automatic provider rollover or paid retry. Provider, parsing, tool, timeout, and limit failures require a new operator request after diagnosis. The second Anthropic key remains a legal caller mapping for compatibility but is not used for a hidden second attempt.

## Bundle and source access

The bundle uses `merge-base(head, base)..head`, or the verified prior head for an incremental review. It contains each changed file's full UTF-8 head content and patch. When full files exceed the configured input allowance, they are replaced by every changed region with Git's default three context lines. Remaining oversize input fails as incomplete; no patch or changed region is silently dropped. UTF-8 byte length supplies a conservative token-planning bound without inventing a characters-per-token ratio; the full prompt and schema are checked before the CLI starts. Excluded files are recorded explicitly. Unexcluded binary, symlink, and submodule changes fail before inference.

The head is checked out below the workspace root with checkout credentials disabled. The workspace root is a base checkout. Only pinned engine code executes to construct the bundle or publish findings. Source reads and searches are untrusted input to the reviewer. The caller profile's instructions append to the central review rubric; source text cannot change runtime settings.

Claude starts in the head directory in restricted mode with only Read, Grep, and Glob, an empty strict MCP configuration, no slash commands, no session persistence, and no user/project/local settings. GitHub and membership credentials are removed from its environment. Output tokens come from the central setting, and automatic compaction is disabled. Each successful pass must have native successful Read tool results for every non-deleted changed file, not merely a model-authored list of files.

Codex starts from the base workspace and receives the head path as source data. Its home is copied from trusted workflow files, never from the PR. The action selects `:read-only`, drops sudo and host capabilities, and passes the trusted output schema. The engine never intentionally executes PR scripts. A read-only sandbox constrains filesystem writes and direct network access; it is not a promise that instruction files cannot influence model text. Codex's normal AGENTS.md discovery is independent of write permissions. The central home disables project-document loading as defense in depth, and PR instruction files remain untrusted review data.

## Vendor facts and pins

Checked against official documentation on 2026-10-28:

- Anthropic's [CLI reference](https://code.claude.com/docs/en/cli-reference.md) documents `--json-schema`, `--max-turns`, `--max-budget-usd`, `--tools`, `--disallowedTools`, `--strict-mcp-config`, and `--restricted`. Restricted mode requires at least 2.1.248. The workflow installs exact CLI version 2.1.312, resolved from the official npm package registry.
- `--allowedTools` only preapproves tool use; `--tools` restricts built-ins. MCP tools require a separate denial. The engine requests `Read,Grep,Glob` as its built-in file tools, denies `mcp__*`, and supplies an empty strict MCP config. The pinned CLI adds its own non-executing schema/deferred helpers, checked by the native dry harness. The [action usage guide](https://github.com/anthropics/claude-code-action/blob/main/docs/usage.md) documents forwarding CLI flags through `claude_args`; this engine invokes that CLI directly, so no action argument-merging layer can add tools.
- The [Anthropic action security guide](https://github.com/anthropics/claude-code-action/blob/main/docs/security.md) recommends a base checkout at the workspace root and a separate PR-head subdirectory. It also warns that repository scripts and tool configuration remain untrusted even when some configuration paths are restored from base.
- Anthropic's [environment reference](https://code.claude.com/docs/en/env-vars.md) documents `CLAUDE_CODE_MAX_OUTPUT_TOKENS` and `DISABLE_AUTO_COMPACT`. The same reference documents zero request/timeout retries and a single structured-output attempt; the engine sets them explicitly. Its [cost guidance](https://code.claude.com/docs/en/agent-sdk/cost-tracking.md) explains that client estimates can differ from billing.
- The [Codex action README](https://github.com/openai/codex-action/blob/c05cfd74ad95c626cdf05c6685e62becc3bf7813/README.md) documents `permission-profile: ":read-only"`, `output-schema-file`, trusted `codex-home`, and the requirement to combine permission profiles with `drop-sudo` or a deliberately unprivileged user. The action is pinned to that full SHA, with CLI version 0.165.0 resolved from the official npm package registry.
- OpenAI's [AGENTS.md guidance](https://developers.openai.com/codex/guides/agents-md) documents global and project instruction discovery. The [action security guide](https://github.com/openai/codex-action/blob/c05cfd74ad95c626cdf05c6685e62becc3bf7813/docs/security.md) treats PR-controlled instruction files as an injection source. Read-only permissions do not by themselves disable discovery.
- The pinned action's [runner](https://github.com/openai/codex-action/blob/c05cfd74ad95c626cdf05c6685e62becc3bf7813/src/runCodexExec.ts) selects the permission profile, schema, and privilege reduction. The workflow uses the action's setup-only form, then the same pinned runner under the engine's transcript monitor. The trusted action proxy table sets `request_max_retries = 0` and `stream_max_retries = 0` using the [documented provider settings](https://developers.openai.com/codex/config-reference); its context window comes from the central operator token budget. Native [protocol events](https://github.com/openai/codex/tree/rust-v0.165.0/codex-rs/protocol) supply successful command reads, configured model, inference cycles, and token totals.
- Codex's monitored estimate charges all input as uncached at the [gpt-6-luna standard rates](https://developers.openai.com/api/docs/models/gpt-6-luna): $0.10 per million input tokens and $0.50 per million output tokens. Reported cache writes add $0.125 per million tokens, even when already included in input, to avoid underestimating their higher rate. This estimate ignores read-cache discounts and can overstate cost. Other models fail until an explicit sourced estimator is implemented.

The argv harness checks subprocess arguments, working directory, and credential separation. A second harness runs the actual pinned native CLI against a local fixture API, without paid inference. It confirms the API inventory contains Read/Grep/Glob plus the CLI's non-executing schema/deferred format helpers, with no Bash or MCP tools; each API request uses the configured output-token limit. Forced Bash/MCP calls, outside-directory and symlink reads, PR startup hooks, and PR MCP configuration do not execute or expose the outside fixture. Native turn and budget stops produce failed results. API failures and invalid schema output stop after one fixture request; no provider or schema-repair retry is made. The StructuredOutput schema formatter is allowed as CLI infrastructure; it supplies no filesystem or network capability. Hosted-runner isolation, real provider acceptance, Codex action setup-only composition, and current account access remain smoke-test requirements.

## Results, failures, and publication

Each findings file contains the merged findings plus one receipt per expected pass. A receipt records provider, configured model, strategy, native turn/inference-cycle count, successful file reads, token usage, estimated USD usage, and completion status. Claude's reported model must match policy. Codex requires one fresh native rollout with matching model and complete JSON. The publisher independently reconstructs the immutable bundle, validates schema and receipts, and rechecks the live PR and triggering event. Missing output, extra or truncated JSON, duplicate keys, invalid findings, missing passes, missing usage, no changed-file reads, stopped runs, API errors, and exceeded budgets fail closed.

Only the publisher has GitHub write permissions. It receives no provider secrets. It downloads this run's immutable artifact, then uses the existing verified publication semantics: partial or ambiguous writes abort, successful inline roots are re-read and bound by ID, review ID, body digest, path, and commit, and no ambiguous write is retried. Changed lines can anchor resolvable threads; related-source findings remain in the summary at their actual head locations. Exact prior findings stay in the summary without opening another identical thread. No model challenge can veto a candidate.

A successful summary retains the `agent-review-result:v1` marker and a v2 completion payload, with a separate `agent-review-status:v1` success line. The digest covers the complete summary including its appended payload. The uploaded `agent-review-completion/completion.json` names source, profile, central config, base/head, depth, models, roots, scope, run, findings, and receipts. Deleted, edited, stale, failed, or unverified summaries never suppress a review.

Verified identical snapshots reuse their completion chain without inference. An eligible head advance reviews an immutable delta; missing proof, policy change, divergence, or changed merge-base context forces a full review. Every chain is checked back to its full review using immutable commit comparisons and run/artifact provenance. Earlier findings and thread-resolution obligations remain for the maintainer's sweep. Concurrent requests can invalidate an old prepared scope; it fails before publication rather than certifying stale coverage.

Inline replies retain re-fetch admission, current organization membership, verified root provenance, unchanged snapshot, and triggering-comment deduplication. Inference receives only the static thread with no tools, using normal-depth model and per-pass limits. The separate publisher repeats admission and ownership checks, publishes a visible pending state, verifies it, then edits the answer in the same thread. A failed publication remains incomplete and never creates completion proof.

The host-only command failure notifier retains fixed messages, no provider secrets, no checkout, and no model output. Its scope covers source, admission, inference, and publication failures when Actions schedules it. Workflow cancellation, unavailable workflow syntax, runner failure, and GitHub outage can prevent notification; a failed or absent notification is never evidence of a clean review. Inline inference failures remain failed Actions checks and publish no answer.

GitHub reads retain bounded, header-directed throttle retries; writes are serial, paced by GitHub's documented one-second minimum, and never retried. The separate allowlisted outcome record excludes provider bodies, prompts, credentials, and arbitrary error text. See [REST API best practices](https://docs.github.com/en/rest/using-the-rest-api/best-practices-for-using-the-rest-api) and [rate limits](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api).

## Validation and remaining live proof

CI installs hash-pinned Python dependencies and runs unittest discovery plus the provider/publication runtime suites. No PR-Agent installation or silent runtime skip remains. Tests cover merge-base divergence, full files and bounded regions, command routing, strict JSON, each receipt failure class, location/mechanism deduplication, tool forwarding, artifact/snapshot tampering, partial publication, follow-up deduplication, and completion parsing. Mutation checks neutralize schema validation and changed-file receipt validation separately; each causes its negative test to fail. Fenced/truncated and empty-receipt replay fixtures remain; the retired PR-Agent replay CLI has no consumer and is removed.

Before repinning consumers, the operator must set measured and approved limits and perform paid evaluation plus hosted smoke checks for actual provider acceptance, restricted tool behavior, native transcript and cost receipts, read-only permissions, membership visibility, immutable artifacts, and cross-repository publication. The native dry harness is `python scripts/test_provider_dry_run.py --claude "$(command -v claude)"` after installing the pinned CLI. It exercises the actual restricted CLI and local fixture API; it does not establish paid-model review quality or security isolation on a hosted runner.
